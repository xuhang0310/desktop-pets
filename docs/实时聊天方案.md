# 实时聊天桌宠改造方案

目标：在现有“鲸鲸与小小”桌面伙伴上，加入**接入大模型的自由对话**和**复刻音色的实时语音**，同时保留现有的待办、番茄钟、动作和预录语音。

适用机器：Windows，RTX 5060 8GB。

---

## 1. 现状

```
麦克风 → System.Speech 白名单识别（voice-commands.json）
      → respond(id)（pet-interactions.js）
      → 从 pet-dialogue.js / human-dialogue.js 选固定台词
      → 播放预录 MP3 + animate() 动作
```

| 能直接复用 | 需要替换或新增 |
| --- | --- |
| 透明窗口、拖动、托盘、快捷键（main.js） | 白名单识别 → 自由语音识别 |
| `animate()` / `setPose()` / `say()` / `stopVoice()` | 固定台词 → 大模型生成 |
| preload.js 的 IPC 桥接 | 预录 MP3 → 实时 TTS |
| 36 段预录 MP3（用作即时反应和离线兜底） | 新增：对话记忆、API Key 管理、设置界面 |
| IndexTTS-2 复刻流程（离线制作素材） | |

实测数据：IndexTTS-2 在本机的实时率约 9～11（3.8 秒的音频要合成 53 秒），不能用于实时对话，只保留给离线制作素材。

---

## 2. 目标架构

```
┌──────────── 渲染进程 ────────────┐  IPC  ┌──────────────── 主进程 ────────────────┐
│ 输入框 / 麦克风                  │◄────►│ asr-service    语音识别 + VAD（CPU）     │
│ 流式气泡 say()                    │       │ chat-service   大模型流式 + 人设 + 记忆  │
│ 音频队列 + 口型（音量→talking）  │       │ tts-service    按句合成，引擎可替换      │
│ animate(action)                   │       │ config         API Key（safeStorage）    │
└───────────────────────────────────┘       └─────────────────────────────────────────┘
                                                        │ HTTP（127.0.0.1）
                                              GPT-SoVITS 本地服务（显卡）
```

### 全链路流式（压低延迟的关键）

```
用户说完 ─► ASR 定稿 ─► 大模型开始输出 ─► 遇到 。！？ 切出第一句 ─► TTS ─► 开始播放
                        └─ 后续句子继续生成和合成，排队播放
```

目标延迟：用户说完后 **1～1.5 秒**听到第一句。

### 资源分配（8GB 显卡）

| 模块 | 运行位置 | 理由 |
| --- | --- | --- |
| 大模型 | 云端 API | 本地跑会和 TTS 抢显存 |
| 语音识别 | 本地 CPU（sherpa-onnx / FunASR 小模型） | 不占显卡，录音不出本机 |
| TTS | 本地 GPU，GPT-SoVITS 常驻服务 | 约 2～4GB 显存，能实时 |
| 固定反应（摸头、戳） | 预录 IndexTTS-2 MP3 | 零延迟，音质最好 |

## 3. 大模型

### 3.1 模型选择

- 统一走 **OpenAI 兼容接口**（`baseURL` + `apiKey` + `model`），千问、DeepSeek、豆包、Kimi 等都可以通过修改配置切换，不用改代码。
- 推荐默认：国内访问稳定、中文好、价格低的千问或 DeepSeek，具体型号以官方文档为准。

### 3.2 思考模式：思考完能不能直接回答？

**能，但聊天场景默认关闭思考。**

- 思考型模型（推理模型）的输出分成两部分：**思考过程**（`reasoning_content` 或 `<think>…</think>`）和**正式回答**（`content`）。程序只把正式回答显示在气泡里、送去 TTS，思考过程不会念出来。
- 代价是延迟：思考通常要几秒到几十秒，这段时间没有任何回答输出，桌宠会“发呆”。
- 方案：
  1. **日常闲聊用非思考模式**（例如千问的 `enable_thinking: false`、DeepSeek 的非推理模型），首字最快。
  2. **复杂问题才开思考**，可以通过设置开关、关键词（“帮我算”“分析一下”），或者让非思考模型先判断后路由。
  3. 思考期间先播放一句预录的“让我想想哦……”，并切到“思考”姿态，避免冷场。
  4. 思考内容可以折叠显示在清单面板里（可选），不朗读。
- 代码层面：`chat-service` 在解析流时分开处理 `reasoning` 和 `content` 两类增量，只有 `content` 进入切句和 TTS。

### 3.3 人设

每个角色一份 system prompt，来源是 `assets/character-prompt.txt` 和现有台词：

- 鲸鲸（大肥鱼 / 蒂普斯克）：口头禅“吃白米饭，鲸鲸”，懒、爱玩游戏、一有活儿就想找千问或豆包帮忙。
- 小小：温柔自然的成年女性，不用鲸鲸的口头禅。
- 通用约束：**回答口语化，每次 1～3 句**（太长会拖慢 TTS，也不像聊天）；不输出 Markdown、表情符号和列表。

### 3.4 控制动作与功能

回复里允许带动作标签，前端剥离后调用现有函数：

```
[action:dance] 好耶，跳舞我最在行了！
```

| 标签 | 调用 |
| --- | --- |
| `[action:pat]`、`dance`、`sleep`、`wake`、`wave` | `animate()` |
| `[todo:add:内容]`、`[focus:start]`、`[focus:pause]`、`[list:open]` | 复用 `onCommand()` 的现有逻辑 |

后续可以改成 function calling，更可靠。标签不会进入 TTS。

### 3.5 记忆

- 短期：最近 10～20 轮原文。
- 长期：超出部分让模型压缩成摘要，例如“用户叫什么、喜欢什么、最近在忙什么”。
- 存储：`userData/chat-memory-<角色>.json`，切换角色时记忆互不影响。设置里提供“清空记忆”。

## 4. 音色：GPT-SoVITS

### 4.1 为什么不用 IndexTTS-2 做实时

| 模型 | 相似度 | 本机速度 | 推理显存 | 用途 |
| --- | --- | --- | --- | --- |
| IndexTTS-2 | ★★★★★ | 实时率约 10（实测） | 8GB 以上 | 离线制作素材 |
| **GPT-SoVITS** | ★★★★（微调后） | 能实时 | 约 2～4GB | **实时对话** |
| CosyVoice2-0.5B | ★★★★ | 接近实时 | 约 4～6GB | 备选 |

RTX 50 系需要支持 CUDA 12.8 的 PyTorch，要下载较新版本的 GPT-SoVITS 整合包。

### 4.2 训练素材：让 IndexTTS-2 当“老师”

鲸鲸的参考音频只有约 4 秒，不够微调。做法：

1. 用 IndexTTS-2 离线批量生成 **80～150 句、合计 5～10 分钟**的鲸鲸语音，覆盖陈述、疑问、开心、撒娇、困倦等语气，长短句都有。在现有 `scripts/generate-indextts-voice.py` 基础上新增脚本 `scripts/generate-sovits-dataset.py`，支持断点续做，可以挂一夜。
2. 输出 GPT-SoVITS 需要的 `wav + 标注列表`（`路径|说话人|语言|文本`）。
3. 在 GPT-SoVITS WebUI 中微调（8GB 显存把 batch 调小，约几十分钟）。
4. 用同样的方法给小小准备素材，或者小小继续用 edge-tts。

音质上限等于 IndexTTS-2 的输出。如果能获得更多授权原声，混入训练效果更好。

### 4.3 服务化

- 启动 GPT-SoVITS 自带的 API 服务（`api_v2.py`），只监听 `127.0.0.1`。
- 桌宠启动时检测服务是否在线：不在线时自动回退到 edge-tts，并在气泡里提示一次。
- `tts-service` 定义统一接口，引擎可替换：

```js
synthesize(text, { voice, signal }) → Promise<ArrayBuffer>   // 一句话一次
```

实现：`EdgeTTS`（第一阶段）、`GptSovitsTTS`（第二阶段），以后可加云端复刻。

## 5. 语音输入

- 用 **sherpa-onnx**（Node 有官方绑定）加流式中文模型，在 CPU 上运行，替换 `scripts/recognize-voice.ps1`。
- **silero-vad** 判断开口和说完，从“点一下说一句”升级为“按住说话”或“免按键连续对话”两种模式，可在设置里切换。
- **打断**：角色说话时检测到用户开口，就调用 `stopVoice()`，并通过 AbortController 取消大模型请求和未完成的 TTS。
- 保留现有快捷口令：识别结果如果正好命中 `voice-commands.json`（如“开始专注”），直接走老逻辑，不经过大模型，最快也最稳。
- 识别期间暂停播放，避免听到自己的声音（沿用现有做法）。

---

## 6. 表现层

- 新增文字输入框（Enter 发送），气泡支持流式逐字显示，长回复自动延长显示时间。
- 新增姿态：“思考中”（等待大模型时）。
- 口型：Web Audio `AnalyserNode` 读取播放音量，超过阈值时切换 `talking` 或张嘴姿态。
- 远期：Live2D 或 VRM 模型，用音素做口型同步。

---

## 7. 安全与配置

- API Key 只存在主进程，用 Electron `safeStorage` 加密写入 `userData/config.json`，渲染进程拿不到。
- 渲染进程只通过 IPC 发送文字、接收增量和音频，并对参数做长度校验（沿用现有 IPC 校验风格）。
- 本地服务只绑定 `127.0.0.1`。
- 设置面板包括：模型服务商、Key、模型名、思考模式（关 / 自动 / 开）、TTS 引擎、语音输入模式、清空记忆。
- 鲸鲸的音色来自抖音视频片段。个人使用没问题；公开分发前需要取得声音所有者的授权。

## 9. 分阶段计划

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| **一：文字聊天** | chat-service、人设、动作标签、思考分流、edge-tts 朗读、输入框、配置面板 | 打字提问，1～2 秒内开始逐句显示和朗读；标签能触发动作；思考过程不被朗读 |
| **二：复刻音色** | 生成训练素材 → 微调 GPT-SoVITS → 接入 GptSovitsTTS，加播放队列、打断和回退 | 鲸鲸用自己的声音实时回答，首句延迟小于 1.5 秒；服务离线时自动回退 |
| **三：语音对话** | sherpa-onnx + VAD、按住说话和免按键模式、语音打断、快捷口令直达 | 不用打字就能连续聊天，能随时打断 |
| **四：体验增强** | 长期记忆、主动搭话（番茄钟结束、久坐提醒、早晚问候）、口型、思考姿态 | 角色会记得用户，会主动关心 |

## 10. 风险

| 风险 | 应对 |
| --- | --- |
| GPT-SoVITS 在 50 系显卡上装不上 | 用支持 cu128 的新版整合包；不行就先用 CosyVoice2 或云端复刻 |
| 微调后的音色不够像 | 增加素材多样性，混入授权原声，调参考音频 |
| 大模型回复太长、太书面 | 在 prompt 里限制长度，并截断过长输出；只朗读前 N 句 |
| 思考模式太慢 | 默认关闭；开启时先播放“让我想想”并切换姿态 |
| 网络断开 | 回退到快捷口令和预录 MP3，气泡提示离线 |
